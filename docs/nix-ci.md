# Native Nix CI

Nostr CI uses `.ngit/nix/workflows/`; the root flake supplies all executable
apps and pins Node 24, pnpm 9.15.9, Gradle 8.14.3, JDK 21, Android SDK/build
tools, ngit-grasp, ngit 3.0.3 and Netlify CLI 26.2.0. GitHub mirror workflows
are independent. The former `.ngit/act/workflows/ci.yml` is removed.

Netlify 26.2.0's upstream lockfile omits download URLs and integrity hashes for
some packages. `nix/ci/netlify-lock-metadata.json` pins that missing registry
metadata by exact package name/version; `repair-netlify-lock.py` restores only
missing fields before dependency fetching and offline installation. Regenerate
this metadata and the Nix dependency-cache hash together when updating Netlify.

| Workflow                 | Automatic trigger                   | Behavior after both test gates                       |
| ------------------------ | ----------------------------------- | ---------------------------------------------------- |
| `ci.yaml`                | Other branches and non-release tags | Checks only                                          |
| `preview.yaml`           | Pull request                        | Publish disposable nsite preview                     |
| `production.yaml`        | Push to `main`                      | Deploy tested site to Netlify and production nsite   |
| `android-release.yaml`   | Push tag `v*`                       | Build unsigned APK/AAB, sign, publish NIP-82 release |
| `android-rehearsal.yaml` | Manual only                         | Build and sign APK/AAB without publishing            |

Every workflow retains npm fallback-lockfile validation, TypeScript, ESLint,
Prettier, unit tests, a web build, GRASP integration tests, and Android lint.
The e2e binary is explicit and mandatory. Preview and production jobs consume
exactly the web files generated by the successful test job; they do not rebuild.
The obsolete act action-download-cache warming job has no Nix equivalent.
PRs additionally build `ci-entrypoints`, realizing every app closure (including
production tools) without executing publishers. A cold provider must fetch the
SDK/tooling and build Netlify; this can be substantially slower than warm CI.

Tests, builds and deployments currently execute as `run` apps: tools come from immutable Nix closures, pnpm
installs use the committed frozen lockfile, and Gradle resolves the repository's
pinned dependency versions at runtime. These are **not hermetic Android builds**:
Gradle currently has no transitive dependency lock/verification manifest. App
execution, dependency downloads and test results are not cached as derivation
outputs. Moving these builds to pure derivations requires first capturing and
validating Gradle dependencies, not silently enabling network in a derivation.

## Secrets and artifacts

Grant the same existing secrets to trusted Nix providers:

- Netlify: `NETLIFY_AUTH_TOKEN`, `NETLIFY_SITE_ID`.
- Production nsite and release publisher: `NGIT_PUBLISHER_NBUNKSEC`.
- Android signing only: `ANDROID_KEYSTORE_BASE64`,
  `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`.

Apps read granted files under `NGIT_CI_SECRETS_DIR` after realization. No
credential is an input to a derivation. Android compilation receives no
keystore; explicit `-PunsignedCiRelease=true` produces unsigned APK/AAB files.
Ordinary local release builds still require the established signing config.
A separate signing job aligns and signs the APK, signs the AAB, verifies both,
and emits only versioned release products. The keystore is decoded to a private
temporary directory and removed on exit. Both password uses share the existing
keystore-password secret. Alias and password values never become process argv.

The publisher retains `.ngit/release.yaml` metadata, Zapstore settings, release
channel selection, and the exact signed APK. The AAB stays a CI artifact.
The publisher fetches the exact tag from the configured Git object mirror with a
120-second bound and verifies its peeled commit against the signed allocation;
a missing or moved tag cannot publish. The tag must exactly equal `v` plus `APP_VERSION` in `version.properties`.
Manual replay of the release workflow cannot publish; use the separate rehearsal
workflow to avoid requesting the publisher secret at all. Production apps also
require a signed push-to-main trigger, so manual replay cannot deploy them.

Directory artifacts use archive transport across provider boundaries. Ensure
provider artifact limits accommodate the website and APK/AAB pairs (default
individual-artifact limits can be too small). Ordinary PR previews require
hardware-VM providers, request no repository secrets, and create a disposable
identity. Preview publication retains its bounded gateway-availability check
and signed `nsite_preview` output.

## Deployment ordering

The former act YAML declared production concurrency groups with
`cancel-in-progress`, but ngit-ci's per-job act execution and act itself did not
enforce those cross-run groups. Native version-1 workflows also lack that
facility. Closely spaced main pushes can therefore finish out of order; this is
an existing limitation, not a serialization guarantee provided by this
migration. Track the coordinator work in the
[deployment ordering issue](https://gitworkshop.dev/nevent1qqstcpxusg7xal7frj9d0p3hnmc5dqmnr3fjl4y7f9jgn7s0vzdcjjgpz3mhxue69uhhyetvv9ujumn8d96zuer9wczmd5rk).

## Local validation

`nix build .#ci-entrypoints` realizes pinned tools without
publishing. Apps themselves are effects: do not run production, signing, or
release apps merely to validate the flake. `nix/ci/test-policy.py` checks the
runtime publication guards with stub tools and temporary artifacts.
`nix develop --command bash nix/ci/test-signing.sh` constructs a synthetic APK
and temporary test keystore, exercises the actual signing code, and verifies
both APK and JAR signatures without using repository signing credentials. The normal
pre-commit hook validates the application. Android lint/build execution needs
the Android SDK plus Maven access; it is intentionally separate from that hook.
